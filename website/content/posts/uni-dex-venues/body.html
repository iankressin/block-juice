Most UNI still changes hands in v3 pools, but v4's share of the token's on-chain volume rose over the window, from a fifth to nearly a third, with one dip in the week of Oct 20. v2 held steady at a little over a tenth. Across the window, the Binance close and the Chainlink UNI/USD feed stayed within half a percent of each other every day, so either is a usable price for valuing these trades.

How it was counted

  • UNI traded is the UNI side of every Swap in analytics.dex_trades on Ethereum, whichever side it was on, in UNI (18 decimals).
  • Version is the pool's Uniswap version, v2, v3 or v4, as the source that loaded it recorded.
  • Weeks are Monday to Sunday UTC, turned into Ethereum block ranges with bj blocks.
  • Price is the Binance UNIUSDT daily close from analytics.token_prices, beside the last Chainlink UNI/USD round of each day from analytics.oracle_prices.

The data

Trades come from the three Uniswap stream sources, which read pool creations and Swaps of pools that trade UNI through SQD Portal, up to Portal's finalized head. Prices come from the binance-candles call source and the evm-chainlink-price-feeds stream source. The provenance block is filled by bj answer from the run log.

Caveats

  • Only pools whose tokens are listed in each version's addresses.json are loaded. A UNI pool against an unlisted token is not counted.
  • Volume is counted in UNI, not USD, so a week with a higher price is not inflated. Multiply by the daily close to get dollars.
  • Trades routed through an aggregator show up once per pool they touch, like any other Swap.

Reproduce it

The analyses behind the charts 
-- transformation/analyses/uni_traded_by_version.sql
-- :start and :end come from `bj blocks ethereum 2026-10-06 2026-11-02`
select
    version,
    round(sum(case when token_bought = '0x1f9840a85d5af5bf1d1762f925bdaddc4201f984'
                   then amount_bought else amount_sold end) / 1e18 / 1e6, 2) as uni_millions
from "warehouse"."analytics"."dex_trades"
where chain = 'ethereum'
  and protocol = 'uniswap'
  and block_number between :start and :end
group by version
order by version

-- transformation/analyses/uni_price_binance_vs_chainlink.sql
with binance as (
    select date_trunc('day', close_time) as day, close
    from "warehouse"."analytics"."token_prices"
    where exchange = 'binance' and token = 'UNI' and quote = 'USDT' and interval = '1d'
),
chainlink as (
    select distinct on (date_trunc('day', block_timestamp))
        date_trunc('day', block_timestamp) as day, price
    from "warehouse"."analytics"."oracle_prices"
    where chain = 'ethereum' and feed = 'UNI / USD'
    order by date_trunc('day', block_timestamp), block_timestamp desc
)
select b.day, b.close as binance_close, c.price as chainlink_price
from binance b join chainlink c using (day)
order by b.day
