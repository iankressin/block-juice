A self-hosted ELT framework and warehouse for blockchain data

Every number traces back to raw rows, and you can rebuild it.

BlockJuice loads chain data into your Postgres, transforms it with dbt and schedules the work with Dagster. Balances, transfers, trades, prices and labels sit next to the rest of your data, under keys and policies you set.

1 · Why

Built for people who have to show their work

If you advise funds, treasuries or protocol teams, you know where on-chain work gets awkward. Explorers are fine for a quick look. Shared analytics platforms work until you need to own the query, the join or how long the data is kept.

In one line

The result is a pipeline an analyst can read, change and hand to a client. Every step is in the repo for anyone to check.

You keep the data

Raw rows, marts, run logs and answers live in a warehouse and repo you run. When an auditor or a client asks how a number was built, you show them the model and the run that produced it.

You ask in plain language

The Claude Code skill (/bj <question>) maps a question onto marts, builds any that are missing, runs the checks and writes an answer folder with the value and the method. From there it can make a PDF, a spreadsheet or a Google Doc.

Coverage is a copied source

Another wallet list, EVM chain or protocol is bj new-source, a chain in dbt and a schedule. The shared library already handles cursors and dead letters, so your time goes to the question.

When it breaks, you can see it

bj doctor checks your env and services before you start debugging. Grafana and the ops.* run log show ingestion and dbt side by side. Failed calls are kept as dead letters, not dropped.

3 · How it runs

Ordinary software engineering, end to end

A TypeScript source writes raw rows into raw.<source>_<table>. dbt reads them as sources and builds staging views and marts in analytics. Dagster runs both as one asset graph, one pipeline per mart folder, on a cron you choose.

Term

Pipeline. The marts in one models/marts/<pipeline>/ folder and everything upstream of them, run as one Dagster job on one schedule.

Chains and APIs

RPC through eRPC and Dshackle, SQD Portal streams, Binance and Coinbase.

Sources

Typed packages that read one kind of data and fill one raw table.ingestion/ · TypeScript

Warehouse

Raw tables, cursors, dead letters and the run log.Postgres

Models

Staging per source, intermediates per pipeline, marts with tests.transformation/ · dbt

Schedules

One job per pipeline, every asset owned by a schedule.orchestration/ · Dagster

Answers

question.yaml, answer.json, answer.md and results/, then a report.answers/ · bj answer

4 · Quick start

Running in an afternoon

You need Node 24 and pnpm (both pinned in mise.toml), uv and Docker.

Safe to repeat

bj install never overwrites an .env and starts nothing. bj dev runs it again before starting the stack.

# set up the checkout: copies .env files, installs packages, parses dbt
uv run --project orchestration bj install

# start the warehouse, eRPC, Dshackle, monitoring and Dagster
uv run --project orchestration bj dev

# then, in Claude Code
/bj How much ETH do the tracked wallets hold right now?
Then

Open the Dagster UI at localhost:3000 and materialize the assets you need. If something looks wrong, run bj doctor before anything else.

  1. Set up once with bj install, start the stack with bj dev, then open the Dagster UI.
  2. Point sources at the wallets and tokens you care about, in each source's addresses.json.
  3. Materialize a pipeline (balances, transfers, dex, labels, prices, tokens) on a schedule you choose.
  4. Ask the business question in Claude Code. You get an answer folder with its checks, and a report if you want one.
  5. When the brief changes, add a source, a chain or your own pipeline. The skill walks you through each.
